ok-script-app/文件

應用與執行目標配置

應用設定

在 src/config.py 中至少檢查：

  • gui_title：應用視窗名稱。
  • gui_icon：GUI 圖示路徑。
  • supported_resolution：支援的畫面比例和最低解析度。
  • links：專案主頁、反饋渠道和社群連結。
  • onetime_tasks、trigger_tasks：任務註冊列表。

執行目標

windows、adb、browser 必須至少配置一種，也可以同時配置多種。

Windows 原生遊戲

配置 windows 中的：

  • exe：遊戲程序檔名列表。
  • hwnd_class：可選的視窗類名，用於提高視窗匹配準確度。
  • interaction：允許使用的輸入方式及優先順序。
  • capture_method：允許使用的截圖方式及優先順序。
  • HDR 和後臺截圖相關選項。

Android 模擬器或裝置

在 adb.packages 中填寫遊戲包名。MuMu 模擬器可使用原生截圖和輸入；其他模擬器或裝置通常通過 ADB 工作。

瀏覽器遊戲

取消 browser 示例配置的註釋，並設定：

'browser': {
    'url': 'https://example.com/game',
    'nick': 'Browser',
    'resolution': (1280, 720),
},

瀏覽器目標還需要 playwright。將它加入 requirements.in 和鎖定後的 requirements.txt，確保本地環境和 GitHub 打包環境都會安裝該依賴。

替換圖示

用自己的資源替換 icons/icon.png 和 icons/icon.ico。保持檔名不變可以避免額外配置；如需改名，同步修改 src/config.py 和 pyappify.yml 中的路徑。

更新倉庫

修改 pyappify.yml 中應用名稱、profile 名稱和 git_url：

  • 正式釋出建議使用獨立的輕量更新倉庫。
  • 前期測試可以直接使用原始碼倉庫。
  • 使用獨立更新倉庫時，同步修改 .github/workflows/build.yml 中的同步目標和 Secrets。

初始化後，搜尋並替換模板遺留的 ok-script-app、ok-oldking、倉庫 URL、安裝包名稱和社群連結。
