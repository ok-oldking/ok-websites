專案架構

ok-bd2 是基於 ok-script 的 Windows PC 端影像識別自動化應用。專案自身負責 Brown Dust 2 的視窗適配、識圖/OCR 規則、滑鼠互動和任務狀態機；任務排程、基礎截圖、 配置介面等通用能力由 ok-script 提供。

執行鏈路

main.py / main_debug.py
        ↓
src.config.config
        ↓
ok.OK：GUI、设备、截图、OCR、任务执行器
        ↓
BD2Interaction + BD2Scene + BaseBD2Task
        ↓
触发任务 / 一次性任务
        ↓
截图 → ROI → 模板匹配或 OCR → 状态确认 → 鼠标操作
  1. main.py 或 main_debug.py 建立 ok.OK，後者僅額外開啟除錯配置。
  2. src/config.py 註冊視窗、截圖方式、互動類、場景、任務和自定義頁面。
  3. ok-script 連線遊戲視窗並建立任務執行器。
  4. AutoLoginTask 等觸發任務維護登入狀態；可見的一次性任務執行具體業務流程。
  5. 所有正式遊戲互動通過 BaseBD2Task.operate_click() 或滑鼠滾輪/拖動完成。

分層與職責

1. 啟動與裝配

  • main.py、main_debug.py：生產和除錯入口。
  • src/config.py：應用的組合根，只負責裝配元件和註冊任務。
  • src/game_path.py：發現執行中的遊戲或解析安裝路徑。
  • src/compat/：對上游框架或 Windows 版本差異做窄範圍相容。

這一層可以依賴所有被裝配元件，但業務任務不應反向依賴 config。

2. 平臺適配與共享執行時

  • src/interaction/BD2Interaction.py：BD2 的滑鼠點選、滾輪、前臺啟用和游標恢復。
  • src/scene/BD2Scene.py：跨任務共享的登入/戰鬥場景狀態。
  • src/globals.py：執行緒池和週期任務生命週期。
  • src/tasks/BaseBD2Task.py：任務共同基類，提供截圖、OCR、操作封裝、動作節流、 探針輸出和標準快速選卡入口。

PC 客戶端不能可靠接收自動化鍵盤輸入，因此平臺層和業務層都不得自行增加鍵盤傳送、 按鍵對映或熱鍵方案。

3. 純識別與座標工具

  • src/utils/template_resolution.py：離線模板目錄標定、基礎倍率、綠幕目錄標記和 Main* 模板的共享搜尋區域。
  • src/utils/image_utils.py：灰度轉換、模板/遮罩縮放、畫素相似度、多倍率生成， 以及相對/參考座標 ROI 裁剪。
  • src/utils/ocr_utils.py：OCR 文本歸一化、關鍵詞計數和容錯子串匹配。
  • src/utils/vision_utils.py：與框架 Box 相關的輕量座標輔助。

這些模組不持有任務狀態，不點選遊戲，適合優先新增單元測試並被多個任務複用。 參考座標 ROI 必須同時縮放左上角、右下角、寬高和位移，不能只縮放區域尺寸。

4. 業務任務

  • src/tasks/trigger/AutoLoginTask.py：持續觸發的登入狀態機。
  • DailyTask、FreeGachaTask、PVPTask、SquareGoddessTask：日常業務狀態機。
  • BargainLevelTask、QuickSuppressionTask：獨立迴圈任務。
  • BD2ProbeTask、BD2InputTestTask、BD2DiagnosisTask：診斷和適配工具。

任務類負責“先識別並確認狀態，再執行滑鼠動作”。底層影像演算法應放入 src/utils， 穩定的跨任務頁面流應放入 BaseBD2Task；只屬於單個玩法的狀態轉換保留在對應任務中。

5. 跑圖/跑商領域模組

跑圖和跑商已按領域物件拆分在 src/tasks/map_trade/：

  • models.py：不可變資料模型、介面狀態和結果型別。
  • data.py：卡帶、商店、物品、座標和模板規格。
  • vision.py：該領域的模板/OCR 門面，複用通用識別工具。
  • navigator.py：主頁、選卡、地圖、商店之間的導航狀態機。
  • trader.py：購買、出售、料理和收藏重建。
  • collector.py：劇情、角色與活動卡帶的地圖採集。
  • collection_selection.py：每週跑圖的自選卡帶、遮蔽範圍與配置校驗。
  • calendar.py：北京時間下的價表和庫存業務日期。
  • progress.py：每日/每週斷點進度的持久化與恢復。
  • MapTradeTask.py、MapCollectionTask.py：配置卡片、依賴裝配和階段編排。

推薦依賴方向為：

Task shell → Trader / Collector → Navigator → Vision → utils
                    ├→ Progress       └→ models / data
                    └→ Calendar

領域模組不應匯入具體 UI 頁面；UI 僅通過任務配置和狀態欄位觀察任務。

6. UI、配置和資源

  • src/ui/：狀態頁、即時截圖、日誌入口和響應式任務配置補丁。
  • configs/：執行時配置與進度檔案；不是業務常量的唯一來源。
  • recognition-assets/template-assets/：正式模板資源。
  • assets/map_trade/：隨程式釋出的跑商業務資料。
  • .local-dev/：不釋出的一次性探針、樣本和實驗輸出。

模板識別約束

  • 根目錄模板在 1920×1080 客戶區的基礎倍率為 1.0。
  • image/ 下模板的統一基礎倍率為 1.25。
  • image/green/ 自動啟用純綠與透明區域遮罩。
  • 正式載入必須經 offline_template_scale() 計算當前客戶區倍率。
  • 識別到目標時點選匹配框中心；穩定固定位置才可使用相對座標。

這些規則集中在 template_resolution.py，任務不得複製另一套目錄倍率判斷。

狀態、失敗與可觀測性

  • 跨任務的“已登入/戰鬥中”狀態由 BD2Scene 儲存。
  • 單個任務的階段和診斷資訊通過 info_set() 暴露給狀態頁與日誌。
  • 跑圖/跑商的持久進度由 ProgressStore 管理，並區分北京時間下的每日和每週週期。
  • 跑圖資源每週一08:00、技能額度每日08:00重新整理；完成記錄包含本次配置範圍與業務週期。升級賬本前保留舊版本備份，回退程式時使用對應版本的賬本。
  • 頁面確認失敗必須返回失敗或記錄失敗階段，不能繼續盲點。
  • 重試應有次數或時限上限，避免無限點選。

擴充套件指南

新增任務時按以下順序選擇落點：

  1. 純座標、影像或 OCR 演算法放入 src/utils，先寫單元測試。
  2. 多個任務共享且長期穩定的頁面流放入 BaseBD2Task。
  3. 單個玩法的狀態機放入獨立任務；超過一個明確領域時再拆子模組。
  4. 任務在 src/config.py 註冊，使用者可調引數放在任務的配置宣告中。
  5. 一次性探針和樣本先放 .local-dev/，確認成為正式能力後再遷入原始碼和測試。

驗證

開發完成前執行：

.\.venv\Scripts\python.exe -m ruff check src tests
.\.venv\Scripts\python.exe -m unittest discover -s tests -v

此外要檢查 src 中沒有專案自定義的鍵盤傳送、按下、釋放、熱鍵註冊或鍵盤對映實現。
