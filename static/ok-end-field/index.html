常见问题

识别或点击不稳定

依次检查：

  1. 分辨率是否为 16:9 且不低于 1600×900（900P）。
  2. 是否使用默认亮度，并关闭显卡滤镜、锐化和画面悬浮层。
  3. 游戏窗口是否未最小化，屏幕是否未锁定或熄灭。
  4. 运行期间鼠标或手动输入是否干扰了前台游戏窗口。
  5. 游戏帧率是否稳定，且游戏和程序权限是否一致。

安装或启动失败

  • 确认使用最新版安装包，并将安装目录加入安全软件信任列表。
  • 避免在 Program Files 或包含中文字符的目录运行程序。
  • 源码运行时重新执行 uv sync，安装与当前项目匹配的依赖。
  • 以管理员权限运行终端、IDE 和程序。

终末地独立启动与官方启动器备用方案

国服及 GRYPHLINK 国际服先通过 Endfield_Data/app.info 确认 Hypergryph / Gryphline，再按以下顺序启动；不根据安装目录名字猜测服务器。

  1. 优先尝试游戏自带的官方签名组件（实验性）：查找 Endfield.exe 同目录的 PlatformProcess.exe，其次是 UnityCrashHandler64.exe。要求有效 Windows Authenticode 签名且证书指纹命中现有官方白名单。将可信文件复制到 OK-EF 的独立 UUID 临时目录、命名为 Games.exe，再次验证副本签名，以挂起状态创建为游戏的直接父进程；不修改游戏安装文件，也不需要安装官方启动器。
  2. 备用：原有官方启动器流程：如找不到有效组件、复制/验证失败或还未创建游戏进程时启动失败，则依次尝试当前游戏渠道对应的官方 Games.exe 与另一已知官方渠道版本。官方启动器的候选、缓存、注册表查找仍要求有效签名、官方指纹及正确产品名称。该备用路径要求安装至少一种官方启动器，但无须点击启动器里的“开始游戏”。

两种父进程来源都复用 OK-EF 原有的进程创建、命令行参数和清理逻辑。游戏进程一旦创建，后续失败、日志超时或 SDK 初始化失败均不会自动创建第二个游戏进程。若游戏已运行，直接连接，不重新启动。Steam/Epic 仍分别通过平台 URI 启动，不走以上两种父进程方式；不能通过平台 URI 传递自定义参数时会明确报错。

两服只读取当前渠道 LocalAppDataLow/<公司标识>/Endfield/sdklogs/OneChannelLC.log 中本轮新增的完整记录。只有看到与本轮临时父 PID 匹配的 Parent process check success:<PID> 才提前回收父进程；此信号只代表父进程检查通过，不代表已登录或完成资源加载。120 秒无成功记录则保留父进程到游戏退出，不凭窗口响应或固定等待时间猜测 SDK 已完成检查。

退出清理和下一次运行的 owned_temporary_launchers/ 恢复记录继续根据 PID、创建时间、完整路径和存活子进程判断归属。自带组件的副本位于 endfield_parent_images/<UUID>/Games.exe；只有安全确认对应父进程已退出后才删除副本，无法删除时保留记录以便下次重试，不按名称终止其他启动器，也不清理不属于本次创建的文件。

测试状态：游戏自带组件方式尚未完成国服/国际服实机验证；无法保证所有游戏版本均接受该父进程。首次参与测试请记录组件选择、Parent process check success、游戏登录结果及自动化是否正常，并提供脱敏日志。该实现参考 Starward 的独立启动提交，未照搬其管理员提权、窗口响应后 30 秒释放策略。

无法识别游戏公司标识，或本地组件与官方启动器均不可用时，请修复安装或手动通过对应客户端启动。启动异常请查看 logs/ok-script.log。
