NPC 與送貨點多語言對照方案

目標：讓配置區域（角色配置區域、送貨點配置區域）在 6 種語言下顯示官方譯名，與遊戲內實際名稱一致，各語言節點相互對應。

1. 現狀

遊戲是《明日方舟：終末地》（Arknights: Endfield，鷹角網路）。配置資料在 src/data/delivery_area.py：

配置區域 資料來源 示例
送貨點（地點） delivery_locations + transfer_search_area 武陵城、試驗園區
角色（目標 NPC） delivery_targets_by_location 常澐、彥寧、齊綸、於施、蘇白易、普里莫（武陵城）；趙昭、裴令容、阿禾（試驗園區）
送貨點配置鍵 _to_delivery_point_config_key → 通向{地点}送货点 通向武陵城送貨點、通向試驗園區送貨點

1.1 多語言通道

  • OCR/識別文本：assets/lang/world_map.json（85 鍵，6 語言節點），經 get_world_map_text/get_world_map_matcher 讀取（src/data/world_map_utils.py），get_delivery_targets(area, lang_accessor) 已支援傳入 lang_accessor。
  • UI 顯示：配置鍵名（中文）經 gettext og.app.tr() 翻譯，i18n/*/LC_MESSAGES/ok.po。
  • 語言啟用：src/data/lang/__init__.py ACTIVE_LOCALES_CONFIG 目前僅啟用 zh_CN/zh_TW，en_US/ja_JP/ko_KR/es_ES 節點存在但未啟用。

1.2 現有問題

  1. NPC 名無任何語言節點：world_map.json 中沒有常澐/彥寧等條目，OCR 與本地化會 fallback 到中文。
  2. 現有地點譯名與官方不符（機翻/拼音）：
中文 現有 en_US 官方英文

試驗園區 Experimental Park Test Area

四號谷地 valley four Valley IV

日/韓/西同理（実験公園 / 실험공원 / Parque Experimental 均為非官方譯法）。

  • 官方地圖 API 僅釋出 英/簡中/日/韓 四語（sk-language 短程式碼驗證），不含 es；sk-language 用長程式碼（ja-jp）返回空串而非報錯，排查語言問題時應優先用短程式碼。

3. 各語言"對上"的規則

落地時每條翻譯必須滿足"各語言節點相互對應"：

  1. zh_CN：保持現有中文（配置鍵名、OCR 主語言）。
  2. zh_TW：官方繁中，用系統轉換（常澐→常澐、彥寧→彥寧、齊綸→齊綸、於施→於施、蘇白易→蘇白易、普里莫→普里莫、趙昭→趙昭、裴令容→裴令容、阿禾→阿禾；武陵城→武陵城、試驗園區→試驗園區、資源回收站→資源回收站、倉儲節點→倉儲節點）。
  3. en_US：本方案核實填寫的官方英文（上表）。
  4. ja_JP / ko_KR / es_ES：按 §2.1 對照表填入已多源核實的官方譯名；表中標「待核實」的節點留空（預設），LangAccessor 自動回退 zh_CN（_load_module 的 fallback 鏈：當前 locale → zh_CN/zh_TW → 首個可用）。留空優於機翻錯誤譯名。
  5. 停用手工翻譯校驗：任何語言節點的值必須是"官方譯名或空"，不允許拼音/機翻佔位（現有 Wulingcheng / Experimental Park 屬此類，需修正）。

4. 落地設計

4.1 world_map.json 擴充套件

為每個 NPC/地點新增鍵（鍵名沿用現有 hash 風格），如：

"k_changyun": {
  "zh_CN": {"pattern": "常沄"},
  "zh_TW": {"pattern": "常沄"},
  "en_US": {"pattern": "Chang Yun"}
}

pattern 欄位用於 OCR 匹配（get_world_map_matcher），string 欄位用於顯示文本——按目標用途選擇。

4.2 配送鏈路適配

  • delivery_area.py 中 delivery_locations / delivery_targets_by_location 保持中文 canonical 名（鍵名不變，避免觸發 config_key_migrations）。
  • 所有對外顯示/OCR 處已通過 get_delivery_locations(area, lang_accessor) / get_delivery_targets(area, lang_accessor) 本地化（delivery_area_service.py:40-69 已支援）。
  • 待辦：DeliveryTask._configure_delivery_area 目前呼叫 get_delivery_targets(self.delivery_area) 未傳 lang_accessor，需補傳，使 ends 列表本地化。
  • 通向{地点}送货点 配置鍵：鍵名保持中文不變（儲存穩定性），顯示翻譯繼續走 gettext ok.po；po 中已存在的「通向武陵城送貨點」等 msgid 由 scripts/sync_world_map_langs.py 的 po 同步邏輯（§5.4）內嵌替換內舊譯名片段。

4.3 啟用語言

ACTIVE_LOCALES_CONFIG 保持現狀（zh_CN/zh_TW），en_US 啟用前需確保全部英文譯名經官方核實。

5. 自動翻譯替換方案（工程化）

5.1 資料層（一次性指令碼）

3. 各語言"對上"的規則

落地時每條翻譯必須滿足"各語言節點相互對應"：

  1. zh_CN：保持現有中文（配置鍵名、OCR 主語言）。
  2. zh_TW：官方繁中，用系統轉換（常澐→常澐、彥寧→彥寧、齊綸→齊綸、於施→於施、蘇白易→蘇白易、普里莫→普里莫、趙昭→趙昭、裴令容→裴令容、阿禾→阿禾；武陵城→武陵城、試驗園區→試驗園區、資源回收站→資源回收站、倉儲節點→倉儲節點）。
  3. en_US：本方案核實填寫的官方英文（上表）。
  4. ja_JP / ko_KR / es_ES：按 §2.1 對照表填入已多源核實的官方譯名；表中標「待核實」的節點留空（預設），LangAccessor 自動回退 zh_CN（_load_module 的 fallback 鏈：當前 locale → zh_CN/zh_TW → 首個可用）。留空優於機翻錯誤譯名。
  5. 停用手工翻譯校驗：任何語言節點的值必須是"官方譯名或空"，不允許拼音/機翻佔位（現有 Wulingcheng / Experimental Park 屬此類，需修正）。

4. 落地設計

4.1 world_map.json 擴充套件

為每個 NPC/地點新增鍵（鍵名沿用現有 hash 風格），如：

"k_changyun": {
  "zh_CN": {"pattern": "常沄"},
  "zh_TW": {"pattern": "常沄"},
  "en_US": {"pattern": "Chang Yun"}
}

pattern 欄位用於 OCR 匹配（get_world_map_matcher），string 欄位用於顯示文本——按目標用途選擇。

4.2 配送鏈路適配

  • delivery_area.py 中 delivery_locations / delivery_targets_by_location 保持中文 canonical 名（鍵名不變，避免觸發 config_key_migrations）。

  1. 精確匹配：msgid（去尾 \n）與官方 zh 名一致 → 整條 msgstr 替換為官方譯名（ja 官方未翻譯的名可能直接是中文/片假名，屬官方資料）。
  2. 內嵌替換：msgid 含官方 zh 名（子串）且 msgstr 含該名舊譯名 → 文本替換為新譯名，如「通向試驗園區送貨點」的 Test Zone → Test Area、ja「武陵買入價」的 ウーリン → 武陵。按 zh 名長度降序處理，避免短名子串衝突。

  4. 冪等：官方譯名已是最新時不產生任何 diff。
