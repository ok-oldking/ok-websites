專案鍵盤操作體系說明

返回：文件索引 / README

本專案支援高度可配置的遊戲鍵盤操作，所有熱鍵均可通過配置自定義，支援多場景（通用、工業、戰鬥）下的快捷鍵對映。本文件詳細介紹鍵盤操作的設計、預設鍵位、擴充套件方式及開發注意事項。

1. 按鍵配置體系概覽

  • 可配置熱鍵統一管理：業務程式碼通過 KeyConfigManager 解析通用、工業和戰鬥鍵位；移動鍵、系統修飾鍵及少數遊戲固定鍵保留底層傳送路徑。
  • 三大類熱鍵：
    • 通用（common）：如地圖、互動、背包等
    • 整合工業（industry）：如工業規劃、放置傳送帶等
    • 戰鬥（combat）：如連攜技等
  • 國際化支援：所有鍵名均有 i18n 支援，便於多語言適配。

3. 按鍵呼叫方式

3.1 業務層介面

  • press_key(key, **kwargs)：傳送通用按鍵（如地圖、互動等）。
  • press_industry_key(key, **kwargs)：傳送工業專用熱鍵。
  • press_combat_key(key, **kwargs)：傳送戰鬥專用熱鍵。
  • press_esc()：僅過劇情（對話時）觸發 ESC。

前三個介面定義在 RuntimeMixin，簽名為 (key, down_time=0.02, after_sleep=0, interval=-1)，並把解析後的鍵傳給 send_key()。press_esc() 定義在 GameFlowMixin，只允許用於劇情對話跳過。專案當前沒有 press_game_key() 公共方法。

3.2 按鍵對映流程

flowchart TD
    A[业务层调用 press_key / press_industry_key / press_combat_key] --> B[选择 common / industry / combat 默认键表]
    B --> C[KeyConfigManager.resolve_key]
    C --> D{默认按键是否匹配配置项}
    D -->|是| E[读取用户自定义键]
    D -->|否| F[保留原始按键]
    E --> G[调用 send_key 发送实际按键]
    F --> G
  1. 業務層呼叫如 press_key('m')。
  2. 通過 KeyConfigManager.resolve_key('m', 'common') 在對應預設鍵表中反查配置項名。
  3. 若使用者有自定義，則取自定義值，否則用預設值。
  4. 最終通過底層 send_key進行物理按鍵模擬。

3.3 未知鍵與異常

  • resolve_key() 不校驗鍵名：預設表中找不到鍵，或 key_type 不是 common/industry/combat 時，原樣返回傳入的 key。
  • RuntimeMixin.send_key() 會先啟用遊戲視窗，再委託框架 BaseTask.send_key()；框架會先用 validate_key() 校驗單字元和已知命名鍵，無效鍵會丟擲 HotkeyConfigException，專案層不捕獲該異常。
  • 校驗通過後，EfInteraction._convert_key() 再把常見別名（如 esc、lctrl、pageup）轉換為 pynput 鍵物件；底層傳送異常仍會向呼叫方傳播。
  • 因此新增業務鍵位時應先加入 KeyConfig.py 的對應預設表；不要依賴未知鍵的透傳作為配置機制。

4. 使用者自定義與國際化

  • 使用者可通過配置檔案自定義所有熱鍵。
  • 支援多語言鍵名，語言資源目錄：i18n。

5. 開發注意事項

  • 可配置遊戲熱鍵不得直接使用 send_key，必須通過 press_key、press_industry_key 或 press_combat_key 呼叫（第 6 節列出的例外除外）。
  • 若熱鍵可自定義，則不可用作模板圖片（否則模板匹配會因使用者自定義失效）。
  • 詳細開發規範：DEVELOPMENT.md。
