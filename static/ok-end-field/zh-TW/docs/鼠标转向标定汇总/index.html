滑鼠轉向標定（MouseRotationCalibration）調查彙總

日期：2026-08-08 涉及任務：src/tasks/test/MouseRotationCalibration.py 結論狀態：核心結論已定，待平地複測確認地形假設

一、任務簡介

MouseRotationCalibration 是 debug 可見的測試任務，用於標定「滑鼠橫向位移畫素 ↔ 角色視角轉動角度」的換算係數：

$$k = \frac{\Delta yaw}{dx} = \frac{after - before}{dx}$$

  • 滑鼠右移 dx>0 → 視角左轉 Δyaw<0，故 k 恆為負。
  • 係數為「°/px」，標定後可用於把目標轉向角度換算為滑鼠位移：dx = round(target_yaw / k)。
  • 不持久化，每次執行標定；也支援手動填係數跳過標定直接驗證。

四、跨輪穩定結論

  1. 左轉（dx<0）表现稳定：各轮 -400→+3032°、-600→+45.550.5°、-1000→+76.587°，大位移 k 稳定在 **-0.076-0.084**。
  2. 右转（dx>0）受起點/地形影響大：同一位移在不同起點差 8~12°。
  3. 推薦係數 ≈ -0.082 ~ -0.084 °/px（17:13 輪最對稱、std 最小 0.004）。
    • 1000px ≈ 84°，600px ≈ 50°，400px ≈ 33°，90° ≈ 1080px。
  4. +200 是小位移異常區（k 偏大 40%），已從標定列表移除。
  5. 大角度（99°）誤差始終偏大（±4~14°）→ 正式使用建議分段轉向。

五、鏡頭偏心假設分析（使用者提出：畫面裡角色始終偏左）

使用者的觀察本身成立——很多 3D 遊戲鏡頭偏心（給前方更多視野），角色顯得偏左/偏下。但資料上排除固定鏡頭偏心：

  1. 固定偏心在 Δyaw 中相消：若鏡頭固定偏心造成箭頭讀數帶上固定偏差 δ（不隨朝向變），則 (after+δ) - (before+δ) = after - before，δ 直接消失，不影響 k。
  2. 決定性證據——不對稱隨起點反轉：固定偏心是空間固定、方向無關的量，若它讓右轉偏大，換任何起點都應右轉偏大。但 112°→257°（差約 145°）偏大方向整個反轉。沒有任何固定偏心能解釋。
  3. 唯一自洽解釋仍是地形：箭頭讀的是角色按 W 前進的面朝方向，坡度把角色帶偏；不同起點走過坡的方式不同 → 偏大方向隨之反轉。
  4. 程式碼層已排除傳送不對稱：send_mouse_delta 用 user32.mouse_event(MOUSEEVENTF_MOVE, dx, 0, 0, 0) 正負直接透傳，完全對稱。

一錘定音驗證方法

找一塊完全平坦、開闊的地方（廣場/平地）重跑「標定 + 左右成對驗證」：

  • k_pos ≈ k_neg（差 < 2%）、8 角度基本全 PASS → 地形假設確認，鏡頭偏心排除；
  • 仍明顯不對稱 → 才輪到鏡頭/遊戲機制問題。

肉眼輔助：按 W 前進時盯箭頭方向，若箭頭慢慢漂移（而非紋絲不動），即地形在帶偏角色——最直接的證據。

六、符號事故復盤

  • 使用者曾在 手动yaw_per_pixel 填 "0.083"（應為負數）。
  • 症狀：+44° 目標用 dx=+530 右移反而轉到 -41°，誤差 84°~207°，方向全反。
  • 處理：1) 配置檔案修正為 "-0.083"；2) 程式碼在手動係數為正時自動取負修正並 notify 日誌，杜絕再犯。

七、後續建議

  1. 換平地重測確認地形假設（當前唯一待辦實驗）。
  2. 起點朝向對齊：正式轉向任務建議先對齊起點朝向再轉向，降低地形影響。
  3. 正式轉向用小角度分段：每步 ≤30°（≈360px），並按方向分系數（k_pos / k_neg）使用。
  4. 狀態判定小修：建議「兩次驗證都 FAIL 才判 FAIL，單次 FAIL 判 WARN」改為「兩次都 FAIL 判 FAIL」更嚴格，當前實現可能漏報。
