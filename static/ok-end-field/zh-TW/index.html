常見問題

識別或點選不穩定

依次檢查：

  1. 解析度是否為 16:9 且不低於 1600×900（900P）。
  2. 是否使用預設亮度，並關閉顯示卡濾鏡、銳化和畫面懸浮層。
  3. 遊戲視窗是否未最小化，螢幕是否未鎖定或熄滅。
  4. 執行期間滑鼠或手動輸入是否干擾了前臺遊戲視窗。
  5. 遊戲幀率是否穩定，且遊戲和程式許可權是否一致。

安裝或啟動失敗

  • 確認使用最新版安裝包，並將安裝目錄加入安全軟體信任列表。
  • 避免在 Program Files 或包含中文字元的目錄執行程式。
  • 原始碼執行時重新執行 uv sync，安裝與當前專案匹配的依賴。
  • 以管理員許可權執行終端、IDE 和程式。

終末地獨立啟動與官方啟動器備用方案

國服及 GRYPHLINK 國際服先通過 Endfield_Data/app.info 確認 Hypergryph / Gryphline，再按以下順序啟動；不根據安裝目錄名字猜測伺服器。

  1. 優先嚐試遊戲自帶的官方簽名元件（實驗性）：查詢 Endfield.exe 同目錄的 PlatformProcess.exe，其次是 UnityCrashHandler64.exe。要求有效 Windows Authenticode 簽名且證書指紋命中現有官方白名單。將可信檔案複製到 OK-EF 的獨立 UUID 臨時目錄、命名為 Games.exe，再次驗證副本簽名，以掛起狀態建立為遊戲的直接父程序；不修改遊戲安裝檔案，也不需要安裝官方啟動器。
  2. 備用：原有官方啟動器流程：如找不到有效元件、複製/驗證失敗或還未建立遊戲程序時啟動失敗，則依次嘗試當前遊戲渠道對應的官方 Games.exe 與另一已知官方渠道版本。官方啟動器的候選、快取、登錄檔查詢仍要求有效簽名、官方指紋及正確產品名稱。該備用路徑要求安裝至少一種官方啟動器，但無須點選啟動器裡的“開始遊戲”。

兩種父程序來源都複用 OK-EF 原有的程序建立、命令列引數和清理邏輯。遊戲程序一旦建立，後續失敗、日誌超時或 SDK 初始化失敗均不會自動建立第二個遊戲程序。若遊戲已執行，直接連線，不重新啟動。Steam/Epic 仍分別通過平臺 URI 啟動，不走以上兩種父程序方式；不能通過平臺 URI 傳遞自定義引數時會明確報錯。

兩服只讀取當前渠道 LocalAppDataLow/<公司标识>/Endfield/sdklogs/OneChannelLC.log 中本輪新增的完整記錄。只有看到與本輪臨時父 PID 匹配的 Parent process check success:<PID> 才提前回收父程序；此訊號只代表父程序檢查通過，不代表已登入或完成資源載入。120 秒無成功記錄則保留父程序到遊戲退出，不憑視窗響應或固定等待時間猜測 SDK 已完成檢查。

退出清理和下一次執行的 owned_temporary_launchers/ 恢復記錄繼續根據 PID、建立時間、完整路徑和存活子程序判斷歸屬。自帶元件的副本位於 endfield_parent_images/<UUID>/Games.exe；只有安全確認對應父程序已退出後才刪除副本，無法刪除時保留記錄以便下次重試，不按名稱終止其他啟動器，也不清理不屬於本次建立的檔案。

測試狀態：遊戲自帶元件方式尚未完成國服/國際服實機驗證；無法保證所有遊戲版本均接受該父程序。首次參與測試請記錄元件選擇、Parent process check success、遊戲登入結果及自動化是否正常，並提供脫敏日誌。該實現參考 Starward 的獨立啟動提交，未照搬其管理員提權、視窗響應後 30 秒釋放策略。

無法識別遊戲公司標識，或本地元件與官方啟動器均不可用時，請修復安裝或手動通過對應客戶端啟動。啟動異常請檢視 logs/ok-script.log。
