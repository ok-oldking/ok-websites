鼠标转向标定（MouseRotationCalibration）调查汇总

日期：2026-08-08 涉及任务：src/tasks/test/MouseRotationCalibration.py 结论状态：核心结论已定，待平地复测确认地形假设

一、任务简介

MouseRotationCalibration 是 debug 可见的测试任务，用于标定「鼠标横向位移像素 ↔ 角色视角转动角度」的换算系数：

$$k = \frac{\Delta yaw}{dx} = \frac{after - before}{dx}$$

  • 鼠标右移 dx>0 → 视角左转 Δyaw<0，故 k 恒为负。
  • 系数为「°/px」，标定后可用于把目标转向角度换算为鼠标位移：dx = round(target_yaw / k)。
  • 不持久化，每次运行标定；也支持手动填系数跳过标定直接验证。

四、跨轮稳定结论

  1. 左转（dx<0）表现稳定：各轮 -400→+3032°、-600→+45.550.5°、-1000→+76.587°，大位移 k 稳定在 **-0.076-0.084**。
  2. 右转（dx>0）受起点/地形影响大：同一位移在不同起点差 8~12°。
  3. 推荐系数 ≈ -0.082 ~ -0.084 °/px（17:13 轮最对称、std 最小 0.004）。
    • 1000px ≈ 84°，600px ≈ 50°，400px ≈ 33°，90° ≈ 1080px。
  4. +200 是小位移异常区（k 偏大 40%），已从标定列表移除。
  5. 大角度（99°）误差始终偏大（±4~14°）→ 正式使用建议分段转向。

五、镜头偏心假设分析（用户提出：画面里角色始终偏左）

用户的观察本身成立——很多 3D 游戏镜头偏心（给前方更多视野），角色显得偏左/偏下。但数据上排除固定镜头偏心：

  1. 固定偏心在 Δyaw 中相消：若镜头固定偏心造成箭头读数带上固定偏差 δ（不随朝向变），则 (after+δ) - (before+δ) = after - before，δ 直接消失，不影响 k。
  2. 决定性证据——不对称随起点反转：固定偏心是空间固定、方向无关的量，若它让右转偏大，换任何起点都应右转偏大。但 112°→257°（差约 145°）偏大方向整个反转。没有任何固定偏心能解释。
  3. 唯一自洽解释仍是地形：箭头读的是角色按 W 前进的面朝方向，坡度把角色带偏；不同起点走过坡的方式不同 → 偏大方向随之反转。
  4. 代码层已排除发送不对称：send_mouse_delta 用 user32.mouse_event(MOUSEEVENTF_MOVE, dx, 0, 0, 0) 正负直接透传，完全对称。

一锤定音验证方法

找一块完全平坦、开阔的地方（广场/平地）重跑「标定 + 左右成对验证」：

  • k_pos ≈ k_neg（差 < 2%）、8 角度基本全 PASS → 地形假设确认，镜头偏心排除；
  • 仍明显不对称 → 才轮到镜头/游戏机制问题。

肉眼辅助：按 W 前进时盯箭头方向，若箭头慢慢漂移（而非纹丝不动），即地形在带偏角色——最直接的证据。

七、后续建议

  1. 换平地重测确认地形假设（当前唯一待办实验）。
  2. 起点朝向对齐：正式转向任务建议先对齐起点朝向再转向，降低地形影响。
  3. 正式转向用小角度分段：每步 ≤30°（≈360px），并按方向分系数（k_pos / k_neg）使用。
  4. 状态判定小修：建议「两次验证都 FAIL 才判 FAIL，单次 FAIL 判 WARN」改为「两次都 FAIL 判 FAIL」更严格，当前实现可能漏报。
