如何讓程式設計代理開發可複用自動化

English · 文件中心 · 連線 MCP

在本地程式設計代理中開啟自動化應用目錄，提供專案路徑、目標應用和期望結果。代理需要訪問本地檔案、啟動程序，並連線該專案的 ok-script MCP 服務。將下面的路徑和任務內容替換成你的實際需求。

連線專案

在 E:\automation\my-app 中工作，使用專案自己的虛擬環境和現有依賴。啟動專案的 ok-script MCP 開發入口；如果沒有，先幫我配置。在 logs/mcp/connections 中讀取有效連線記錄，核實專案和程序，用其中的 URL 和 bearer token 連線，不要輸出憑據。呼叫 list_skills，再通過 get_skill 讀取相關技能。確認 screenshot 獲取的是正確目標。不要使用 Computer Use 技能、外掛或工具。

如果代理沒有原生 MCP 連線能力，讓它用已安裝的官方 MCP Python SDK 編寫本地客戶端，仍然通過 MCP 服務提交任務檔案。埠、認證和程序生命週期見 MCP 說明（英文）。

查詢任務所需的 API

通過 ok-script MCP 呼叫 list_skills，讀取 get_skill("develop")，以及相關模板或測試技能。我需要找到設定按鈕、點選它，並驗證新介面。定位這個專案的 Python 直譯器實際使用的 ok-script 包，檢查截圖、匹配、等待和輸入方法的原始碼、文件字串和 Python 簽名，包括繼承的方法。列出所需方法的匯入路徑、準確簽名、返回行為和本地原始碼位置，再給出適用於當前安裝版本的最小示例。不要猜測 API 名稱，也不要為了套用示例而更換版本。

MCP 提供工作流技能和執行工具，沒有 get_api 工具或完整的 Python API 目錄。代理通過本地檔案訪問檢查已安裝包，獲取與專案版本一致的 API。若匯入模組需要尚未安裝的可選依賴，可先讀原始碼，再判斷是否需要安裝。無需檢出框架原始碼倉庫。

開發並驗證新任務

在 E:\automation\my-app 中，為我的 Windows 應用開發可複用 Python 任務 EnableOptionTask。從主介面進入設定，啟用“顯示詳情”，儲存，再次開啟設定，確認“顯示詳情”仍為開啟狀態。重複執行應保持開啟，不能把選項再次關閉。

先讀取相關 MCP 技能並核實已安裝 API，再實現任務。程式碼儲存在專案正式任務模組中。用 ok-script 截圖和互動，優先驗證 PostMessage 後臺輸入。優先使用幾何、顏色或模板匹配，確有需要再加 OCR。不要使用 Computer Use 工具，也不要給執行中的指令碼新增大模型呼叫。

通過 MCP 測試，提供 reset_to_start、verify_start_state 和可觀察的成功斷言。每次嘗試前恢復並驗證起始狀態，儲存失敗日誌和截圖，設定有上限的等待，並驗證重複執行。將完成的任務註冊到專案配置，使普通 GUI/CLI 執行也能恢復狀態。最後給出儲存的檔案路徑、驗證結果、尚未驗證的限制，以及不依賴代理的準確執行命令。無法驗證 GUI 開始按鈕時如實說明。

其他任務也請說明四件事：目標、起始狀態、操作、成功條件。還可以補充支援的解析度、後臺執行要求和禁止執行的操作。最終交付物應是可複用 Python 程式碼、素材、配置和執行說明。

修改已有任務

應用更新設定佈局後，已儲存的 EnableOptionTask 失敗了。呼叫 list_tasks 找到原始原始碼，檢查失敗證據並原地修改。用返回的 task_id 呼叫 reload_tasks，等待過載成功後恢復目標狀態，通過呼叫已註冊任務的輕量 MCP 測試檔案驗證。不要在臨時檔案裡複製整套任務邏輯。複用恢復方法，驗證重複執行；識別邏輯變化時補充截圖迴歸測試。保持日常執行不呼叫大模型。

重複執行成果

讓代理給出真實的已註冊任務名和配置入口。例如，在應用專案目錄執行：

.\.venv\Scripts\python.exe -m ok run_task EnableOptionTask --config src.config:config

這裡的 CLI 命令選擇已註冊任務；MCP 的 run_task(file_path) 執行任務檔案，兩者入口不同。也可以關閉 MCP 後從應用 GUI 啟動儲存的任務。切換到普通執行前先結束開發執行時，詳見快速開始。

開發對話會消耗模型 Token；複用本地 Python 自動化無需代理或大模型推理。後續介面變化可能需要新一輪開發；如果你主動要求指令碼呼叫大模型，則該部分仍有推理成本。
