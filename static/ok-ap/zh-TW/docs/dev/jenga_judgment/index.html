實際接觸判定

PlayableItemControllerComponet.CalculateSurfaceOverlap（0x183ED3820）：

  1. 從碰撞接觸點取得法線。abs(normal.y) < 0.5 時返回 0，側面碰撞不算搭建。
  2. 兩個 BoxCollider 分別選取朝向法線及反法線的面（BestFace）。
  3. 將面的四角投影到接觸平面（ProjectFace），取凸包（ConvexHull）。
  4. 用 Sutherland–Hodgman 演算法求兩個凸多邊形的交集（SHClip）。
  5. 返回 clamp01(交集面积 / min(面 A 面积, 面 B 面积))。 分母不大於 1e-4 時返回 0。

這是碰撞盒接觸面的面積比例，不是截圖輪廓寬度、螢幕包圍框 IoU 或兩個中心的距離。 耳朵、裝飾、透視與塔身傾斜都會使視覺上重疊的比例不同於實際接觸比例。

HandleHouseCollision（0x183ED49D0）在碰撞事件中計算比例；若指定了有效目標， 碰到的碰撞盒所屬物件必須等於 m_ValidTargetGo，否則把比例和結果清零。 成功後剛體設為 kinematic，失敗則彈開並啟動銷燬計時。因此事後看起來短暫落在塔上並不能證明成功。

边界注意：控制器自己的 EvaluatePlacement（0x183ED4360）先使用 ratio <= m_MissThreshold 判 Miss，再以 ratio >= 0.8 判 Perfect。 但存在有效藍圖規則時，回撥 <TriggerOnceControllerComponet>b__0（0x183EED870） 會按上表重新計算並返回最終結果。因此不能把控制器的 <= 0.5 當作藍圖最終邊界。

回撥僅在最終結果為 Perfect 時設定 m_PerfectFlags 的對應位。 資料包提取的三星說明為“所有的圖騰都被放置，並都是完美判定”；計數到達 20/20 或 出現 COMPLETE 不足以證明三星，必須檢查最終三顆星。

進一步檢查 HandlePlayableOver（0x183EDC100）：普通模式先讀取結果字典中 Perfect（列舉 2）的數量，與最大雕像數比較；達到最大數才進入最高檔分支。 否則再比較 Perfect + Good（列舉 1）的數量是否達到最大數。 TotalSculptureCount（0x183EE6470）則對所有結果增加下落計數，印證了 “HUD 達到 20/20”與“20 次 Perfect”是不同條件。

無限模式還有 m_IsUnlimitedMode 門控的強制失敗分支：超過普通上限、接近硬上限時 按進度增加主動彈飛機率（ForceMissAfterSuccess），達到硬上限必觸發。 不能把這個機制與普通 20 層挑戰的視覺誤判混為一談。

實際運動

CalculateFigure8Offset（0x183ED3770）、CalculateCurrentVelocity（0x183ED3690）：

phase += moveSpeed * fixedDeltaTime
localOffset = (horizontalRadius * sin(phase), verticalRadius * sin(2*phase), 0)
worldPosition = initialPosition + initialRotation * localOffset
worldVelocity = initialRotation * (
    horizontalRadius * moveSpeed * cos(phase),
    2 * verticalRadius * moveSpeed * cos(2*phase), 0)

軌跡是八字，縱向頻率為橫向兩倍，不是資料中示例的橢圓。 藍圖值為 moveSpeed=1.6、橫向半徑 1.25、縱向半徑 0.4。

StopMovement（0x183ED6610）保留當前速度的 x/z 分量，將 y 清零， 再投影去掉場景深度方向。釋放後橫向速度不會歸零。

SetControllerParams（0x183ED62C0）把名為 fallSpeed 的引數寫入 m_GravityScale，藍圖值 5 實際表示重力倍率。 UpdateFallMove（0x183ED69A0）每個固定步增加 vy += -9.81 * gravityScale * dt， 並以 m_MaxFallSpeed 限速；建構函式預設值為 -10。 忽略離散步與接觸修正時，g = 49.05，約 0.2039 秒達到速度上限，之後勻速。 下落時間隨釋放高度變化，不能固定為 0.5 秒。

物理更新還有最多 4 個子步（最大步距 0.15）、掃掠檢測、防穿透、0.01 的接觸餘量及 0.03 的近接觸閾值（PreventPenetration，0x183ED5230）。應通過實機幀序列校準 離散步及輸入延遲，不能只用連續公式就宣稱穩定 Perfect。
